# A journal of small files, not one memory file

Status: accepted

## Context
One `MEMORY.md`, ledger or changelog edited by everybody conflicts in every pair of parallel branches, grows without bound and gets skipped when a session forgets to update it. The team still needs a precise chronological record that ties decisions to issues, PRs, comments and releases.

## Decision
- History lives in `.agent-os/journal/YYYY/MM/<ISO-timestamp>-<author>-<slug>.md`, one entry per file, with front matter: `type` (decision · lesson · incident · release · handoff · note), `refs` (issues, PRs), `areas`, `author`.
- Every PR carries its own journal entry in its own commits (`/pr` writes it). The loop check in CI fails a PR without one, unless the PR is marked trivial by a rule the config defines (for example dependency bumps), in which case the entry is generated by the release.
- Decision records use date-based ids.
- Indexes and timelines (`agent-os journal list`, `agent-os chronicle`) are generated on demand, combining the journal with git and GitHub, and never committed.
- Lessons wait in `.agent-os/lessons/inbox/` until `/retro` triages them.

## Consequences
No conflicts, and no update can be forgotten, because the PR cannot merge without its entry. The record is complete and chronological, and the reasoning is linked to the GitHub artifacts it came from.
