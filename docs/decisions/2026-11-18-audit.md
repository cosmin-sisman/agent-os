# One versatile audit skill with lenses and evidence

Status: accepted

## Context
Teams need assessments of very different things: an idea, a set of specifications, a project at any stage, a release, a specific problem, a complex cross-cutting question. Ad-hoc audits mix perspectives, cite no evidence and end as chat text that nobody tracks.

## Decision
- `/audit <subject>` detects the subject (idea, spec, project, release, problem, system) and confirms it.
- It runs separate **lenses** (product, architecture, stack, code quality, security and privacy, performance and cost, delivery, process, operations), each in a subagent with its own checklist. Presets per subject choose lenses, and the user can adjust them.
- Findings carry evidence, a severity and a confidence; duplicates are merged; each finding gets one recommendation chosen with the standards' decision procedure.
- Output is an audit artifact (versioned, verified against the audited commit), proposed issues on confirmation, lessons, and a journal entry. Re-runs compare with the previous audit.

## Consequences
Audits become comparable over time and actionable through the normal flow. The maintenance profile's `/audit` is this skill with the `project` preset.
