# Area map

Where each part of this repository lives. Linked from [AGENTS.md](../AGENTS.md); keep a row per top-level area, and add one when a new area appears.

| Path | What |
|---|---|
| `bin/agent-os.mjs` | the executable; it only calls `src/cli/main.mjs` |
| `src/cli/` | the runner (`main.mjs`), the command registry with lifecycle states (`registry.mjs`), global options, the `Context` every command receives, exit codes and `CliError`, questions (`prompt.mjs`) with menus on a real terminal (`menu.mjs`) |
| `src/conventions/` | title and commit message conventions (`agent-os check`) |
| `src/config/` | the configuration schema (one definition for validation, defaults and the published JSON Schemas) and the loader for `agent-os.json` + `.agent-os/local.json` |
| `src/templates/` | the template engine (`engine.mjs`) and folder rendering with language variants (`tree.mjs`); test fixtures in `__fixtures__/` (not published) |
| `src/platform/` | platform detection: remotes, known hosts, probing unknown hosts (`detect.mjs`); a fake network for tests in `__fixtures__/` |
| `migrations/` | one migration per version that changes projects (`<version>.mjs`), with a fixture project each in `__fixtures__/`; contract in its README |
| `src/migrations/` | the migrations runner: order, idempotency, dry runs, the lock record |
| `changelog.yaml` | what each release changes, by group; read by `update --plan` and the release notes |
| `src/lifecycle/` | the lifecycle manifest (`manifest.mjs`) and its exceptions (`lifecycle.yaml`); `manifest.json` at the root is the last release's baseline, rebuilt at release |
| `src/update/` | the update flow: plan (grouped changes from `changelog.yaml` and the manifest), preflight, branch, migrations, apply, journal, gate, change request (`update.mjs`) |
| `src/version/` | the pinned version: the hook command, mismatch checks (`pin.mjs`) |
| `src/managed/install.mjs` | the install plan: core plus the active platform route, rendered; the lock records the platform |
| `src/managed/` | managed files: three-way merge (`merge3.mjs`), the lock, merge bases, Markdown blocks, settings.json hooks, eject and relock (`managed.mjs`) |
| `src/tracker/` | the tracker interface (`tracker.mjs`), the GitHub adapter (`github.mjs` for issues, `github-changes.mjs` for change requests and releases, `github-board.mjs` for the board, `github-shared.mjs` for helpers) with the gh client (`gh.mjs`), the GitLab adapter (`gitlab.mjs`, client in `src/platform/glab.mjs`); fake gh and glab for tests in `__fixtures__/` |
| `src/workflow/` | the work loop: `/next` (`next.mjs`: deterministic ranking, design §9), `/start` (`start.mjs`: claim, branch name and base, link, In Progress, check out), `/pr` (`pr.mjs`: body rules, preflight, open), `/ship` (`ship.mjs`: readiness, merge, Closes vs Refs, clean-up) |
| `src/gate/` | the gate: suites selected from `gatePaths` globs, run, results table, the saved result `/pr` requires (`gate.mjs`) |
| `src/doctor/` | doctor: the registry of checks (`checks.mjs`), the runner, fixes and readiness score (`doctor.mjs`) |
| `src/journal/` | the journal: one file per entry, its schema and validation, list filters, unique names (`journal.mjs`) |
| `src/env/` | environment checks (`checks.mjs`), version ranges (`semver.mjs`) and the probe that looks at the machine (`probe.mjs`); a fake probe for tests in `__fixtures__/` |
| `src/hooks/` | the hooks runner (`runner.mjs`: events, handlers, isolation, adoption mode, the settings block) and guard rules (`guards.mjs`) |
| `src/i18n/` | the language engine: areas, the core label and milestone dictionaries (`labels.yaml`, `milestones.yaml`), the ASCII rule for ro, the agents' language rule |
| `src/yaml/` | the strict YAML subset parser and emitter used for every YAML file (reference: `docs/reference/yaml.md`) |
| `src/util/` | small shared helpers (did-you-mean, path globs) |
| `schema/` | published JSON Schemas, generated by `npm run schema`, never edited by hand |
| `src/commands/` | one file per implemented command, exporting `run(ctx)` and optionally `options` and `usage` |
| `templates/` | files the package installs into projects: `core/` for every project, `platform/github/` and `platform/gitlab/` for one platform; path segments like `__crSkill__` come from the platform vocabulary |
| `docs/design/` | the target design |
| `docs/decisions/` | decision records, date-based ids |
| `docs/research/` | research notes behind decisions |
| `docs/reference/` | user reference; `configuration.md` has a key table generated by `npm run schema` |
| `.github/` | issue forms, PR template, workflows (`ci.yml`, `pages.yml` artifact site) |
| `catalog/` | the stack catalog in YAML: layers, technologies, languages, providers, runtimes, blueprints |
| `examples/` | example files a project would have (`stack.yaml`) |
| `artifacts/` | visual artifacts: one folder each, with `artifact.yaml` and a self-contained `index.html` |
| `scripts/github/` | scripts that set up this repository's GitHub: `plan.mjs` + `setup.mjs` (labels, milestones, issues, relationships), `project.mjs` (the project board, rerun after creating issues) |
| `scripts/bootstrap/` | one-off Python that produced the first catalog and artifact |
| `scripts/site/` | builds the GitHub Pages site (artifacts plus a generated index) |
